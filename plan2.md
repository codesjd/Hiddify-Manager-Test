Let's see what needs to be fixed in `RegisterWithParentApi`:

```python

```
`parent_unique_id` does not exist in `data`. We should use `data['name']` because in `request_child_to_register`, `payload.name` is set to the parent's unique id. Or we can just log `data['parent_panel']`.

Then,
```python
        if hutils.node.is_parent() or hutils.node.is_child():
            logger.error("The panel is not in standalone mode nor in child")
            abort(400, 'The panel is not in standalone mode nor in child')
```
The error message says "nor in child". But if it is a child, it throws an error? Maybe the comment in `RegisterWithParentApi` means a child CAN register with another parent? No, a panel can only be a child of one parent. The error message should probably be `abort(400, 'The panel is already a child or parent.')` or `'The panel is not in standalone mode.'`

Then,

`register_to_parent` calls `__get_parent_panel_url()` which relies on `ConfigEnum.parent_domain` and `ConfigEnum.parent_admin_proxy_path`. So we MUST set them!

```python
        domain, proxy_path, uuid = hutils.flask.extract_parent_info_from_url(data['parent_panel'])
        if not domain or not proxy_path or not uuid or not hutils.node.is_panel_active(domain, proxy_path, uuid):

        set_hconfig(ConfigEnum.parent_admin_proxy_path, proxy_path, commit=False)
```

Wait, in `SettingAdmin.py`, it does exactly this:

```python

```
Here it uses `parent_apikey` which was extracted from the `parent_panel` URL!
But in `RegisterWithParentApi`, `data['apikey']` is passed from the parent. Is `data['apikey']` the same as `uuid` from `data['parent_panel']`?
In `request_child_to_register`:
```python
    payload = RegisterWithParentInputSchema()
    payload.parent_panel = hiddify.get_account_panel_link(AdminUser.by_uuid(g.account.uuid), domain)  # type: ignore
    payload.apikey = payload.name = hconfig(ConfigEnum.unique_id)
```
Wait, `payload.apikey` is `hconfig(ConfigEnum.unique_id)` (which is the parent's unique id, not an admin uuid)!
But `register_to_parent(name, apikey)` calls `NodeApiClient(p_url, apikey).put('/api/v2/parent/register/', payload, RegisterOutputSchema)`.
The `apikey` used for the NodeApiClient is the authorization token.
The parent's `/api/v2/parent/register/` endpoint requires `@login_required({Role.super_admin})`. This means the `apikey` used to call it MUST be a valid super admin UUID on the parent!
If `request_child_to_register` sends `payload.apikey = hconfig(ConfigEnum.unique_id)`, and `RegisterWithParentApi` passes that as the `apikey` to `register_to_parent`, then `register_to_parent` will use the parent's `unique_id` as the auth token! But the parent's `unique_id` is NOT a valid admin UUID!

Wait, let's look at `NodeApiClient`. How does it authenticate?
`NodeApiClient(base_url, apikey)`. It sends `Hiddify-API-Key: {apikey}`.
And the parent API `RegisterApi` is protected by `login_required({Role.super_admin})`.
So `apikey` MUST be a valid super_admin UUID on the parent.
In `SettingAdmin.py`:
`parent_apikey = uuid` (from `extract_parent_info_from_url(p_p)`).
And `parent_panel` URL generated by `get_account_panel_link(AdminUser.by_uuid(g.account.uuid), domain)` is:
`https://{domain}/{proxy_path}/{admin_uuid}/`.
So the `parent_panel` URL *does* contain the admin UUID!
And `request_child_to_register` sets `payload.apikey = hconfig(ConfigEnum.unique_id)`. Wait, if `apikey` is the unique_id, then using `apikey` in `register_to_parent` is WRONG!
It should extract `parent_apikey` from `data['parent_panel']` and pass that to `register_to_parent`, OR `request_child_to_register` should pass the admin uuid in `payload.apikey`. But since `request_child_to_register` is passing the unique_id, let's see why. Maybe the child's name on the parent is the unique id, and it doesn't need to pass apikey because we can extract it from `parent_panel`.
